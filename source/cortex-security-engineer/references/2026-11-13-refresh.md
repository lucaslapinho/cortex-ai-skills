## Updated portfolio routing

This revision expands the existing coordinator without renaming it. Use [Palo Alto portfolio](portfolio-routing.md) for ownership and product boundaries. Separate the security objective from the product selection; do not activate every specialist for a narrow question.

- Cloud posture/inventory/scans and workload runtime: `cortex-cloud-engineer`.
- NGFW, PAN-OS, Panorama, SCM configuration and Cloud NGFW traffic inspection: `palo-alto-firewall-engineer`.
- Prisma Access, Prisma SD-WAN, Prisma Browser and workforce AI Access Security: `prisma-sase-engineer`.
- AI application runtime, model/agent artifacts, AI red teaming and AI Gateway: `prisma-airs-engineer`.
- XQL, detection, playbook, hunting, TIM and platform mechanics keep their existing specialists.

The current AIRS architecture uses four pillars (Runtime, Supply Chain, Red Teaming, Gateway). AI Access Security is a workforce control boundary; Cortex Cloud AI-SPM is a posture boundary. Do not merge licenses, APIs, coverage or operational results across them.

Preserve a common handoff contract: exact product/release/management plane, scope, entity keys, time semantics, artifact version, authorization, owner, acceptance evidence and failure/recovery. A cloud finding may motivate a firewall review but does not itself authorize a network change. A successful manager job does not establish downstream traffic enforcement.
