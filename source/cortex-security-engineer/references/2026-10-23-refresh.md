## Operational effect

- Continue separating query permission, raw dataset access, row-level scope,
  saved-object visibility, and command execution permission. One successful layer
  does not prove the next layer is permitted or the end-to-end workflow succeeds.
- If permitted raw records are visible but an XDM query is empty, preserve source
  marker, identity, and time bounds while checking effective dataset-row scope,
  parsing/mapping, retention, and query logic. Do not prescribe removing filters.
- Keep product/deployment boundaries explicit when routing XSOAR orchestration or
  TIM requirements to a specialist. A product overview is not tenant entitlement.
- Treat a query that persists results as a state change even if its preceding
  stages only read data. Verify destination ownership, overwrite/append intent,
  least scope, authorization, and recovery before execution.

No meaningful contradiction with the existing scoped operating rules was found.
