## Classification policy

- `VERIFIED / OFFICIAL-CURRENT / TENANT-UNVERIFIED` means the cited syntax or general behavior was in current first-party material at the review cut; tenant schema, license, configuration, access, data population, compilation, and execution remain unknown.
- `VERSION-DEPENDENT / OFFICIAL-CURRENT / TENANT-UNVERIFIED` means the source is current but its behavior is explicitly bounded by product, release, license, deployment, or execution surface.
- `VERSION-DEPENDENT / OFFICIAL-EXAMPLE / TENANT-UNVERIFIED` means a first-party example is pinned but cannot establish current tenant schema or compatibility.

## Revalidation procedure

Before updating a query or release:

1. Re-open the exact product/version pages, not a search-result snippet or generic portal.
2. Check page product labels and final redirect destinations.
3. Compare syntax, types, restrictions, limits, terminology, and license/RBAC notes to this register.
4. Record new review date and material differences.
5. Re-pin living repositories and inspect the exact reused file.
6. Re-run behavioral, ambiguity, adversarial, and regression tests affected by the change.
7. Preserve unresolved conflicts, especially `regextract()`, until target evidence resolves them.
8. Never upgrade tenant claim level from a documentation refresh alone.

The source URLs establish documentation traceability. They do not grant permission to run queries, access tenant data, create rules, or take response actions.
