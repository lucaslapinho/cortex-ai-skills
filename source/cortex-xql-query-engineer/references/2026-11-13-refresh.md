## Updated decision rules

- `regextract` in the general reference still documents a scalar first-capture result. The historical XDR 3.x array discrepancy is retained; that versioned page was not reopened in this pass. Verify the target return shape before choosing array/scalar downstream operations.
- `dedup` still does not make an earlier sort a deterministic retention contract; use documented `by` behavior where applicable, and handle ties explicitly. Its key-type prose and Boolean example remain inconsistent. Do not erase the discrepancy by assuming runtime behavior.
- `target` is a final write stage and defaults to overwrite (`append=false`). A request to analyze a query does not authorize persistence or replacing an existing dataset.
- The XQL API documents a 1,000-row ordinary result cap, no pagination, larger-result streaming and four concurrent API queries. API-started-only prose still conflicts with broader `query_id` wording; multi-tenant count wording remains inconsistent. Preserve those uncertainties, use the documented API-started flow and verify exact schemas/quotas.
- Verify the intended execution surface separately: Query Center, BIOC, scheduled correlation and real-time correlation do not have one universal stage contract. Cloud/firewall logs still require an observed tenant schema; no provider-specific dataset is introduced by this update.
