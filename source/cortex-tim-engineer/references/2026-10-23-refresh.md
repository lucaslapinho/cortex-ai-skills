## Reconciliation and retained differences

The existing project separation of collection, management, enrichment, lifecycle, distribution, and enforcement remains appropriate. No inspected page makes a successful feed fetch, lifecycle update, or hosted list equivalent to a committed and effective downstream security policy. No score authorizes a control action.

**OpenCTI conflict persists.** TIM-R05's `last_run_id` argument points to `OpenCTI.IndicatorsList.LastRunID`, the declared output section says there is no context output, and the example instead nests `lastRunID` under `OpenCTI.Indicators`. Keep the exact usable output path `UNVERIFIED`; do not choose capitalization/nesting by inference. Resolve with applicable version-pinned implementation and installed command output. The existing [interoperability reference](interoperability-and-distribution.md#opencti) preserves this discrepancy.

**Product wording remains scoped.** OpenCTI type creation, TAXII complex-observation representation, and TAXII server collection/query wording name XSOAR even though availability includes XSIAM. Preserve both observations; XSIAM mapping/selection behavior is not proved by the shared availability banner. The earlier project context is retained rather than rewritten as a generic cross-product capability.

**Service troubleshooting refresh.** TIM-R08/R09 now document three consecutive ports for the described service architecture: configured Listen Port and two following internal ports. They distinguish public listening from internal processes and network mode; do not recommend exposing all three ports. TIM-R08 explains that simultaneous requests for one initially building cache entry can return 429, while a refresh can serve prior cached data. Treat these as diagnostic hypotheses tied to the applicable integration release, never proof of a tenant cause.

TIM-R09 separately documents an inline `q` export limit of 100,000 indicators and directs larger exports to appropriately configured instances. This is a documented request-mode limit, not a measured throughput promise or a universal indicator-store limit. Existing consumer-confinement guidance remains: defaults and credentials do not establish allowed data scope. Exported Fields wording remains XSOAR-specific.

No original OpenCTI playbook, installed-pack inventory, source-to-target sample reconciliation, or live consumer evidence was added. Project-only paths and historical deployment claims remain unverified.
