## Scope and access boundary

This inventory covers the Cortex-related material that was actually readable in the current execution context:

- the complete current workspace, including hidden project records, current Git history, unreachable Git blobs, generated bytecode, references, workflows, templates, tests, and scripts;
- every file in the supplied `INC` directory, including the files named in the request and additional XSIAM exports, a workbook, text batches, and archives found alongside them;

- the pasted master prompt, used as the user-prioritized engineering requirements for this build; its product statements are still requirements to verify, not factual Cortex evidence by themselves;

The following were **not** accessible and were not claimed as ingested:

- any wider ChatGPT Project knowledge, conversation history, or Project File Library content not mounted as a readable file;

No indiscriminate full-volume scan was performed. The bounded sources were the workspace roots, the explicitly supplied directory, and the supplied attachment location. Raw endpoint identifiers and hostnames are operationally sensitive and are intentionally not reproduced here.

## Executive conclusions

1. The pre-existing `Skill DFIR` repository baseline, before creation of these two deliverables, contained **no Cortex-specific product knowledge**. It contributes reusable evidence-first DFIR methodology, source traceability, templates, validation patterns, and skill architecture only. The new `research/` files are the first Cortex-specific workspace artifacts and remain untracked at this review point.
2. The supplied Cortex context is not one coherent package. It contains two distinct provenance families:
   - a loose, derivative context for deprecated `soc-optimization` content pack version `2.1.19`;
   - a separate ZIP context for identity response, DNS, OpenCTI, N1 triage/SLA, and Continuous Assessment.
3. No file in the ZIP is byte-identical to any of the six loose context files. Same-named files are different artifacts and must not be merged.
4. The ZIP is structurally healthy: 21 unique UTF-8 entries, safe relative paths, valid JSON manifest, and a successful full decompression test. Its SHA-256 is `1bf727c0afef71f256f9244671b88d74ae6ecca3d610261db2611f0670b96427`.
5. `FULL_CONTEXT.md` is a convenience duplicate: after normalization it is the concatenation of `SKILL.md` plus the 17 Markdown context files, with a short preamble. It is not independent corroboration.
6. The loose `cortex-project-context-complete-report.md` embeds the loose `SKILL.md`, `index.md`, `codebase-map.md`, and `validation.md`. Those embedded copies are derivative, not four additional sources.
7. The attached `cortex-project-context-artifact-validation.txt` validates a different package revision than the supplied ZIP. The mismatch is recorded in `project-vs-official-differences.md` as an internal provenance conflict.
8. Twelve endpoint/application exports contain 3,457 unique two-column endpoint records in total. Their structure is consistent with the official Host Inventory ability to export tables as TSV, but the generating filters/application names are absent.
9. No supplied XQL query, correlation rule, tenant schema export, or live result exists. Current official documentation may support examples classified `VERIFIED / OFFICIAL-CURRENT / TENANT-UNVERIFIED`, with `C: NOT RUN` and `E: NOT RUN`; claims about tenant availability/schema, compilation, execution, results, performance, installed commands, close reasons, dependencies, or schedules remain tenant- and version-dependent until checked at the required validation level.

## Verification labels

| Label | Meaning |
|---|---|
| `LOCAL-VERIFIED` | The current file bytes or archive member were directly read and the stated structural fact was checked. |
| `VERIFIED / OFFICIAL-CURRENT` | The factual product claim matches a current official Palo Alto Networks source reviewed on 2026-09-04. |
| `PROJECT-ASSERTED` | The claim is preserved from project material but its underlying source or deployment was not available. |
| `VERSION-DEPENDENT` | The claim may be valid for the recorded XSIAM/XSOAR/content-pack version but is not a timeless product fact. |
| `TENANT-UNVERIFIED` | Current tenant schema, installed content, permissions, configuration, or runtime behavior is required. |
| `DERIVATIVE` | The artifact summarizes or duplicates other material and is not independent corroboration. |
| `REFERENCED-ONLY` | A name/hash/description was readable, but the underlying artifact was unavailable. |
| `CONFLICT` | A meaningful internal or official-documentation discrepancy exists; see the differences register. |

For product behavior, precedence in this deliverable is: current official documentation; official examples/repos/API references; directly available project evidence; secondary material. Exact tenant artifacts remain the best evidence of what that tenant/version actually executed, but they do not override current support boundaries.
