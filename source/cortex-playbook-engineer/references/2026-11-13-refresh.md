## Updated decision rules

- XSIAM distinguishes system AI prompts from custom prompts. A locally added task copies the selected prompt configuration; later library changes do not automatically update that task. Inspect the actual task before assuming a prompt update propagated.
- Prompt placeholders such as `[evidence]` identify extracted inputs; `${...}` is context mapping syntax and must refer to observed context. Do not confuse the two or invent a native output path.
- Custom AI output supports an optional JSON schema with top-level `type`, `properties`, `required` and `additionalProperties`; the top-level type is `object`. Verify the installed editor before importing or relying on schema enforcement. The output/context name is an explicit task configuration choice.
- Use the [AI triage template](../templates/ai-triage-contract.md) for a full prompt, input contract and proposed schema. It is a template with caller-defined mappings, not a built-in automation or guaranteed import artifact.
- The debugger can execute real actions under the logged-in identity. A mock/copied issue does not sandbox external integration side effects. Already-running parallel tasks can continue after a breakpoint; manual tasks have separate pause behavior. Use supported skips/overrides and authorized test targets.
- Verify per-instance command permissions in addition to integration installation and health. For Cloud, Firewall or SASE response actions, bind the exact product/manager/scope and reconcile asynchronous jobs before retrying.
- AI conclusions stay advisory; a deterministic authorized policy and verified entity mapping govern containment. Notifications must escape untrusted fields and omit sensitive raw content.
