## Changes and discrepancies

- XSIAM 3.6 Cases release notes prefer `modification_time` over the deprecated
  `last_update_time` alias for Case search and describe a corrected `reply` wrapper.
  Refresh the exact operation schema before changing a client. These are documented
  release changes, not measurements of a tenant or a universal response contract.
- The same API release-notes page lists a Case artifacts successor with **GET** in
  its migration table and **POST** in the 3.5 Cases table. This is an unresolved
  first-party method discrepancy. Preserve both references and verify the operation
  definition for the target release before emitting an executable request. Neither
  table alone justifies silently replacing a legacy call.
- The access page still documents XDM returning rows only when the Datasets Rows
  no-filter option permits all rows and no filter is defined in that area. Inspect
  actual SBAC enablement and scope. Preserve approved access; a diagnostic finding
  is not authorization to remove filters or broaden permissions.
- No contradiction was found for the scoped Broker, Engine, collector-function,
  or command-permission statements above. This does not revalidate their complete
  manuals, capacity tables, supported hosts, or the remaining source-register rows.
